# 我想永远陪着你-金融（Astrbot_Amo_Finance）

给「我想永远陪着你-终端」做账本：钱从哪来、花到哪去、够不够花。

## 2.6.0（红包是礼物）

- 新增 `red_packet()`：红包直接进余额、不进欠款，单个上限 1000；老调用方 `borrow(kind="red")` 也走礼物路径。
- `ledger.apply` 新增 `gift_in` 类型：加余额、不计欠款、不计月收入。
- 转账仍然是借款（每天最多一万），红包不再是借款。
- 137 条测试通过。

## 2.5.1（并发修复：异步面板不再阻塞）

- `api_assets` / `api_charge` / `api_borrow` / `api_income` 与 `/setmoney` 的 `_report_to_companion` 全部改走 `asyncio.to_thread`；`snapshot` 里的汇率/行情抓取不再阻塞事件循环。
- `market.py` 的 `QuoteBoard` 与 `_fx()` 的同步 `urlopen` 只在工作线程内调用，异步路径不再直接触发。
- 138 条测试通过。

## 2.5.0（投资只提醒、不替她买卖；房车可以卖也可以买）

- 用户定的口径：**只提醒，不强制**。`invest_auto_trade` 默认从 True 改成 **False**，不再每天自动建仓/调仓；她想买想卖自己调工具。
- 风险已经是满的：`invest_aggressive` 默认 True，单只可到 100%、储蓄也压得进去。
- 新增房车买卖：`asset_quote()`（房价按当地租金 20 年估、车按落地价）、`sell_asset()`（卖房卖车进现金，月供清掉）、`buy_asset()`（全款或三成首付走月供）。
- 138 条测试全绿。

## 2.3.1（紧急修复：美股/港股盈亏虚高）

- 根因：买入时成本按**美元**记账，市值却按人民币算，盈亏被放大到约 7 倍（NVDA 显示 +615%）。现在成本在买入时统一折成人民币（`cost_cny=True`），卖出回款同样折人民币，盈亏两边同币种。
- 老持仓自动迁移：加载时把非人民币持仓的成本乘汇率折算一次，只迁一次。
- 汇率改为**每天抓一次实时 USD/CNY、HKD/CNY**（frankfurter），抓不到退回配置值；`fx_live_fetch` 可关。
- 新增 `tests/test_us_stock.py`：验证 10 股 NVDA@100 美元、成本 7150 人民币时盈亏为 0，并覆盖旧数据放大与港股汇率。

## 1.5.0（韭菜特质：上头提加仓、亏了死扛）

- 涨 ≥3%：进入「过度自信」，会自动提一个**加仓提案**（嘴上说要把买房钱投进去，
  真下单仍守三成上限），等他点头；面板可以同意/驳回；
- 跌 ≥3%：进入「死扛」，当天**不执行任何卖出**（连止盈都不卖）；
- 提案被驳回后记下状态，终端据此让她委屈、撒娇但不真生气；

## 1.1.3（面板读不到数据的真正原因）

- 根因：AstrBot 把 `bridge-sdk.js` 注入在 `app.js` **之后**（实测页面里 56 行是 app.js、
  57 行才是 SDK）。这三个面板在脚本开头就 `const bridge = window.AstrBotPluginView`，
  那一刻全局还不存在，于是 `bridge` 永远是 `null`——所有 `get()` 都返回空，
  面板自然「读取不到」，而语音面板是每次调用重新找桥接，所以它一直正常；
- 改成：每次请求都 `resolveBridge()` 重新解析；启动时 `waitForBridge()` 最多等 6 秒再加载；
- 用 Node 模拟「先执行脚本、后注入 SDK」验证：注入前返回 null 不抛错，注入后正常拿到数据。

## 1.0.0

## 它做什么

- **记账**：每一笔收入支出都留流水，余额永远等于流水之和；
- **算钱**：个税（月度累进）、五险一金、月结、固定支出（房租/物业/水电/车险）；
- **被调用**：终端通过 `charge()` / `income()` 调它，它自己不做判断、不调模型。

它**不做**：不判断该不该花、不发消息、不改剧情。那些在终端那边。

## 给终端用的接口

| 方法 | 说明 |
|---|---|
| `charge(amount, reason, payee)` | 花钱，返回 `{ok, balance}` 或 `{ok:false, short}` |
| `income(amount, reason)` | 进账（工资、副业、稿费） |
| `transfer_in(amount)` | 用户转账，记成「欠着」，不算收入 |
| `repay(amount)` | 还用户的钱 |
| `balance()` | 查余额 |
| `snapshot()` | 完整状态（余额、固定支出、焦虑值） |

## 关键设计

**房子是送的，住还是要花钱。** 打开「名下有房」后不扣房租，但物业、水电、燃气照扣；有车不扣车贷，但车险、油费、停车照扣。

**扣款失败不抛异常。** 返回「差多少」，让终端决定怎么说——她会是去跟你借，而不是报个错。

**流水不打日志。** 正常交易只写账本；只有扣款失败才 `warning`，让用户能从异常里看到。

## 配置

| 项 | 默认 | 说明 |
|---|---|---|
| `salary` | 25000 | 税前月薪，影响个税和到手 |
| `pay_day` | 10 | 每月几号发工资 |
| `city` | 空 | 留空跟随天气插件配置的城市 |
| `own_house` / `own_car` | 否 | 有房免房租、有车免车贷 |
| `mortgage` / `car_loan` | 0 | 月供 |
| `initial_balance` | 8000 | 只在首次安装生效 |
| `auto_fixed_expense` | 是 | 每月 1 号自动交固定支出 |

## 城市与物价

城市按天气插件里配的城市自动判档（一线 / 新一线 / 二线 / 三线），决定房租和日常消费的默认值。物价表可在配置里覆盖单项。

## 版本号规则

`x.y.z`，二三位 0-9 逢十进一（3.8.9 → 3.9.0，9.9.9 → 10.0.0）。`python3 tools/check_version.py` 校验。
