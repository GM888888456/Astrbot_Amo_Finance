## 1.1.3（面板读不到数据的真正原因）

- 根因：AstrBot 把 `bridge-sdk.js` 注入在 `app.js` **之后**（实测页面里 56 行是 app.js、
  57 行才是 SDK）。这三个面板在脚本开头就 `const bridge = window.AstrBotPluginView`，
  那一刻全局还不存在，于是 `bridge` 永远是 `null`——所有 `get()` 都返回空，
  面板自然「读取不到」，而语音面板是每次调用重新找桥接，所以它一直正常；
- 改成：每次请求都 `resolveBridge()` 重新解析；启动时 `waitForBridge()` 最多等 6 秒再加载；
- 用 Node 模拟「先执行脚本、后注入 SDK」验证：注入前返回 null 不抛错，注入后正常拿到数据。

## 1.0.0

## 它做什么

- **记账**：每一笔收入支出都留流水，余额永远等于流水之和；
- **算钱**：个税（月度累进）、五险一金、月结、固定支出（房租/物业/水电/车险）；
- **被调用**：终端通过 `charge()` / `income()` 调它，它自己不做判断、不调模型。

它**不做**：不判断该不该花、不发消息、不改剧情。那些在终端那边。

## 给终端用的接口

| 方法 | 说明 |
|---|---|
| `charge(amount, reason, payee)` | 花钱，返回 `{ok, balance}` 或 `{ok:false, short}` |
| `income(amount, reason)` | 进账（工资、副业、稿费） |
| `transfer_in(amount)` | 用户转账，记成「欠着」，不算收入 |
| `repay(amount)` | 还用户的钱 |
| `balance()` | 查余额 |
| `snapshot()` | 完整状态（余额、固定支出、焦虑值） |

## 关键设计

**房子是送的，住还是要花钱。** 打开「名下有房」后不扣房租，但物业、水电、燃气照扣；有车不扣车贷，但车险、油费、停车照扣。

**扣款失败不抛异常。** 返回「差多少」，让终端决定怎么说——她会是去跟你借，而不是报个错。

**流水不打日志。** 正常交易只写账本；只有扣款失败才 `warning`，让用户能从异常里看到。

## 配置

| 项 | 默认 | 说明 |
|---|---|---|
| `salary` | 25000 | 税前月薪，影响个税和到手 |
| `pay_day` | 10 | 每月几号发工资 |
| `city` | 空 | 留空跟随天气插件配置的城市 |
| `own_house` / `own_car` | 否 | 有房免房租、有车免车贷 |
| `mortgage` / `car_loan` | 0 | 月供 |
| `initial_balance` | 8000 | 只在首次安装生效 |
| `auto_fixed_expense` | 是 | 每月 1 号自动交固定支出 |

## 城市与物价

城市按天气插件里配的城市自动判档（一线 / 新一线 / 二线 / 三线），决定房租和日常消费的默认值。物价表可在配置里覆盖单项。

## 版本号规则

`x.y.z`，二三位 0-9 逢十进一（3.8.9 → 3.9.0，9.9.9 → 10.0.0）。`python3 tools/check_version.py` 校验。
